# Release notes

One file per manager release, `X.Y.Z.md`, written before the tag: the release
workflow refuses a tag without it and puts it at the top of the GitHub release,
above the lines about the signature and the build.

Write for a car owner: what is new, what is fixed, what to know before updating
(a head unit restart asked, something not yet tried in a car). Headings `### New`,
`### Improved`, `### Fixed`, `### Changed`, `### Good to know`, only those with
something under them; one line per bullet, no commit names or file names.
